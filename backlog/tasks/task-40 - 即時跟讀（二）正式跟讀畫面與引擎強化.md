## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
來源：創辦人 2026-11-16 手機實測（Android Chrome 157）：原型頁「邊唸邊辨識效果不錯」，指示繼續做。設計：docs/pending/2026-11-13-live-shadowing/design.md（含裁示紀錄）、mockup.html（Artifact「拾字・即時跟讀設計稿」）、experiments.md。

【實測數據（創辦人手機，連續模式約 24 秒）】
- 每輪辨識耗時中位數 144 ms、P90 284 ms，遠低於 1.5 秒門檻；體感約 1.5 秒內變色。
- 模型偶發幻聽：輸出阿拉伯文、中文、整句不相干的內容（如 The Lord said...），以及重複迴圈（all all all...、I always use. ×7）；這類輪次耗時 560–760 ms。
- 創辦人回報：偶爾有唸到的字沒被標，回頭重唸該字或該段即可標上，可接受。推測原因是兩輪確認要求「相鄰兩輪」都對到，幻聽輪次打斷了連續性。

【需求】
把即時逐字標記做進課程的跟讀題，取代現有「錄完整句再辨識」成為預設流程；舊流程保留為退路。

【已定案】
B 建議版判定（不照順序；功能字不擋完成、淡色顯示；完成後提示最長一口氣字數並附可選「一口氣再唸一次」，不影響分數）；整句完成＝答對、跳過＝答錯；I'm 與 I am 互通；保留舊流程作為「改用整句錄音」；主引擎 Moonshine 滑動視窗（沿用 TASK-39 的 liveMic、liveStt、liveMatch），Moonshine 不能用時才用 Web Speech 即時結果（沿用現有同意流程）。

【範圍】
做：
1. 引擎強化：丟棄幻聽輪次（非拉丁字母輸出、明顯重複迴圈），並限制單輪輸出長度；兩輪確認放寬為「最近 3 輪中有 2 輪對到」或同等效果的規則，以實驗 2 重跑確認誤標率仍 ≤2%。
2. Web Speech 即時後備（interimResults），沿用 webSpeech.ts 現有同意流程。
3. 正式跟讀畫面：依設計稿的狀態（開始前、錄音中部分完成、剛唸對的字標記、整句完成、辨識不可用退回）；整句完成自動停錄、60 秒上限、20 秒未完成出現「改用整句錄音」；完成後的連貫度提示與「一口氣再唸一次」。
4. 計分與紀錄：整句完成算答對、跳過算答錯；作答紀錄保存每輪聽到的文字摘要（不存錄音）。更新 docs/spec/requirements.md 中與此衝突的條文（G2）。
5. 原型頁 /debug/live-shadowing 保留供日後量測。
不做：不改其他題型、不改語音辨識模型、不上傳錄音。

【邊界】
動 speech、screens/lesson 的跟讀題與題型登記、i18n、規格文件。新增介面文案須逐字列出供創辦人審核後才 merge。
