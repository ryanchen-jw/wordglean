# 知識迭代與反思協議

> 定義後續 session 如何安全地更新這套 harness 與記憶,防止制度腐化。

## §1 檔案權限分級

| 級別 | 範圍 | 規則 |
|---|---|---|
| **綠:可自行更新** | memory 目錄(`~/.claude/projects/C--Projects-LinguaApp/memory`)的踩坑/feedback 檔與 `MEMORY.md` 索引;`00-diagnosis.md §2` 修復清單狀態欄(僅追加註記) | 照 §2 格式寫;寫前照 §4 查重 |

## §2 踩坑紀錄寫入格式

觸發時機:某個錯誤(a)浪費了 > 30 分鐘,或(b)第二次發生,或(c)user 明確糾正。一次性小失誤不記(防記憶通膨)。

寫入 memory 目錄,一坑一檔,固定模板:

```markdown
---
name: <kebab-case-slug>
description: <一行:什麼情境下會踩、一句話避法>
metadata:
  type: feedback
---
<一段:錯誤行為是什麼(具體到指令/檔案)>

**Why**:<當時為什麼錯、代價是什麼(日期、任務、浪費多久)>

**How to apply**:<正確做法,寫成可執行的步驟或一行判準;含「何時適用/何時不適用」邊界>
```

寫完在 `MEMORY.md` 加一行索引。相對日期一律轉絕對日期。

【正例】`feedback_<主題>_before_<動作>.md` —— 有情境、有代價、有一行判準,新 session 讀一行索引就能招回。
【反例】「要更小心地驗證資料」—— 無情境無判準,三個月後沒人知道它在說什麼。

### §2.1 未實測的推論不准寫進 memory

memory 的門檻**高於對話**:對話裡的推論會被下一句話修正,memory 裡的推論會在你看不見的未來被當成既定事實引用,而且引用它的人不知道它從沒被跑過。

**判準**:一條「可以在三十秒內實測」的行為(git 語意、路徑解析、工具旗標效果),要嘛跑一次再寫,要嘛就別寫。寫不確定的東西時把不確定性寫進去,不要只寫結論。

典型實錄形狀:未實測就寫下「squash-merge 會反向 revert 主幹上分支沒有的 commit」,並據以加了一道多餘的前置檢查;開拋棄式 worktree 實測一次(三十秒)即**推翻**——squash 是真三方合併,只捨棄歷史不捨棄合併語意。

同形問題:**註解/文件的保證範圍只到它被寫下的那一刻**。某驗證腳本的註解寫「沿用某某腳本的解法」,只保證那支當時的實作,不涵蓋之後新加的案;但讀的人會把整支檔都算進那句話。

**共同形狀**:把一次性的判斷寫成了長期的保證,於是二手證據在傳遞中悄悄升級成一手。agent 宣稱「逐字核對過」也屬此類,不可盡信。

**推論**:要別人的結論當自己的證據時,先確認那個結論涵蓋你要用的那一段;涵蓋不到就自己跑。

### §2.2 機制優先於敘述

一條「保證」如果靠**敘述**成立(註解、文件、口頭前提、環境剛好如此),它就會在某天前提改變時靜默失效,而且沒有任何東西會變紅。同一件事若由**機制**保證(預設 deny、`:ro` 掛載、無預設值的必填欄位、會紅的測試),失效時當場就會吵。

常見三種形狀:
- 對外發送的安全性只寫在註解「dev 沒有正式憑證」→ 裝了真憑證後**真的發到正式帳號**
- 守衛**宣稱**擋得住 `&&` 串接,實際只比對字串——而該破壞會讓失敗的退出碼被吞成 0,**排程恆綠、實際沒做事,比沒有守衛更糟**
- 容器 bind mount 是 `rw`,「不要往容器裡寫」只是一句叮嚀 → 改成掛 `:ro`,讓它在檔案系統層不可能

**判準**:寫下「這樣就不會發生」時,問一句「**它靠什麼機制不發生?**」。答案若是一段文字或一個沒人保證的前提,就去把它換成機制;換不掉的,至少讓它有一條會紅的測試。

⚠️ **這族的關鍵性質:實例都不是「寫錯了」——前提在寫下的那一刻全都是真的。**

所以 **code review 抓不到它**:讀 diff 的人看到的每一句都對。能抓到的只有兩種——
1. 讓前提失效時**當場會紅**的測試(於是失效的那天自己吵出來)
2. 讓前提在**結構上不可能失效**的機制(`:ro` 掛載、預設 deny、無預設值的必填欄位)

這也是為什麼假護欄多半是隔離驗收官的**破壞測試**抓到的,而不是任何人讀 diff 讀出來的:**你得去弄壞它,才知道它是不是真的。** 對照 03 模板 D 第 7 條。

## §3 精簡與抽象化觸發條件(量化)

命中任一 → 觸發「記憶精簡任務」(黃級:向 user 提案後執行):

1. `MEMORY.md` **整檔超過 20,000 字元**(載入上限約 25,000,這是 80% 水位)
2. **任一索引行超過 200 bytes** → 不必等精簡任務,**當場壓回鉤子長度**(鉤子只列面向、不列要點)
3. 單一 memory 檔超過 **150 行**;檔名或 description 自稱「合集」者不受此限(合集本來就是靠變大來收攏同主題)
4. 距上次精簡超過 **90 天**(以 `meta_last_consolidation.md` 的日期為準)
5. 兩條 memory 描述的判準互相矛盾(發現當下就要提,不等門檻)

量測指令(Git Bash,可直接貼;`wc -m` 算字元、`wc -c` 算 bytes,中文一字 3 bytes——**兩者差三倍,別混用**):

```bash
cd ~/.claude/projects/C--Projects-LinguaApp/memory
wc -m MEMORY.md                                          # 條件 1:整檔字元數
LC_ALL=C awk '{if(length($0)>200)c++}END{print c+0}' MEMORY.md   # 條件 2:超標行數(須為 0)
```

> **為什麼門檻掛鉤「載入得進去嗎」**:原制度的舊門檻(索引 >30 行／單檔 >100 行／距上次 >60 天)訂得比現實嚴太多,
> 三條全部超標卻從未觸發過任何一次精簡——**一個從不觸發的觸發器比沒有觸發器更糟,因為它讓人以為有把關**。
> 新門檻與真正會出事的事情(超載時系統靜默截斷後段索引,**不報錯、也不告訴當下的 session 它少了什麼**)掛鉤,
> 並附可直接貼的量測指令,讓判準維持可勾選(§5 總原則)。

精簡的動作定義(不是刪光):
- **合併**:同主題多檔 → 一檔多節(例:多條 daily-brain 流程 feedback → 併入 daily-brain.md 本體後刪 memory,規則進制度檔就不需要記憶檔)
- **抽象化**:≥3 條同型踩坑 → 升為一條通用判準寫進 `02-judgment-matrix.md`(黃級提案),原檔刪除
- **淘汰**:引用的檔案/函式已不存在、或制度檔已涵蓋 → 刪,並在提案中列明淘汰理由
- 精簡後在 memory 目錄留一檔 `meta_last_consolidation.md` 記錄日期與動了什麼

## §4 規則唯一性原則(寫入前查重程序)

新規則落檔前,先過**寫入三問**(過不了就不寫):

1. no-op 測試:這句拿掉,模型憑常識也會做嗎?會 → 不寫
2. 有現成指引詞(鐵律/對帳/快照鐵則/速查卡/防錨定/自足/紅指令…)就用詞
3. 禁令改正面陳述——寫「該做什麼」;僅 bash_gate 級硬護欄可用 NEVER 形式,且必附「改做什麼」

再依序執行查重程序,全部通過才准寫:

1. `Grep` 關鍵詞於:`.claude/harness/`、workspace `CLAUDE.md`、`daily-brain.md`、`session-report-spec.md`、memory 目錄
2. 命中語意相同的既有規則 → **更新那一處**,不新增副本
3. 命中語意衝突的 → 停,按 `02-judgment-matrix.md §3-6` 回報矛盾
4. 無命中 → 判斷歸屬層級再寫:通用行為 → 全域 CLAUDE.md(黃級);workspace 流程 → harness(黃級);單一子專案事實 → 該專案 CLAUDE.md(黃級);個人踩坑 → memory(綠級)
5. 寫入處以外若有位置需要讓讀者找得到 → 放**一行指標**(`見 <path>`),不複製內容

【反例】把「sub-session 可以 push 的例外」同時寫進 memory、daily-brain、子專案 CLAUDE.md 三處——半年後三處演化出三種版本,弱模型行為取決於載入順序(見 `00-diagnosis.md §1 痛點 2`)。

## §5 制度退化症狀速查

**總原則:判準必須可勾選——任何修改讓某條判準從可勾選變成需要品味,那次修改就是退化,不論理由多合理。**

| 退化 | 早期症狀 | 處置 |
|---|---|---|
| 儀式化 | 驗收回報無本輪實跑輸出;出現「應該沒問題」 | 退件(03 模板 D) |
| 條件空泛化 | 派工 prompt 出現不可勾選條件 | 無效派工(01 §3) |
| 複本回歸 | MEMORY.md 超 §3 門檻;同規則兩處措辭不同 | §3 觸發器+§4 查重 |
| 升降級不執行 | 回報出現第 3 次「再試一次」 | 熔斷(01 §4、02 §3) |
| 判準稀釋 | 規則 diff 中量詞消失、冒出「適當」「合理」 | 黃級提案審查專盯量詞 |
